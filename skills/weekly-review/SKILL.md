# Weekly review

Read AGENTS.md and docs/reviews.md. Inputs: owner, reporting window, active goal, permitted sources, prior decisions and known coverage gaps. Confirm processor policy first.

1. Resume an existing period directory when present; otherwise run review PERIOD. Complete delta.md with dates, definitions, baseline, changed sources, commitments and unavailable coverage.
2. Run agents/research.md first. Record user needs, exceptions, sample limits and source/revision pointers in research.md.
3. Run only relevant domain roles. Give each delta.md, research.md, a focused question and its own report path. Use separate sessions or host-supported subagents; either route uses the same artifacts.
4. Run agents/coordinator.md last. Produce one decision agenda with exact current/replacement wording, evidence, implications and unresolved questions. Record actual completed roles and next phase.
5. Prepare cited topic proposals. Show the full diffs and stop for the owner's explicit decision. Record and apply accepted packets only after that decision. Run health and link resulting actions to their canonical owners.
6. Next week distinguish the decision, completed work and measured outcome. Revisit the original hypothesis instead of counting activity as success.

Output: scoped reports, one decision agenda, pending proposals and a private checkpoint. No autonomous approval, outbound sending or service writes.

Synthetic example: a freelancer has one new scope request and no new commercial evidence. Use research and delivery; keep pricing assumptions explicitly undecided rather than inventing sales activity.

Missing-data case: when analytics are unavailable, name the missing window/owner/recovery step. A partial review remains partial.
