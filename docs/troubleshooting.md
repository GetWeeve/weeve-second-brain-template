# Troubleshooting

- **Python missing.** Install Python 3.9+ from python.org. On Windows use `py -3`; on Mac/Linux use `python3`. Run doctor.
- **Choose the permitted processor first.** Run settings to inspect. After the owner's choice, use `settings --processor local --confirm-data-policy` or `settings --allow-cloud --confirm-data-policy`. These select a command policy; they do not switch your actual agent/model.
- **External processing disabled / import denied.** Use a separate external-safe workspace and explicitly external-approved extracts. Do not change a processor flag to bypass confidential-source restrictions.
- **Noninteractive approval refused.** Show the diff and get an explicit human decision. The owner can type the packet ID in their terminal, or authorize recording that exact decision with `approve PACKET-ID --by "Owner" --confirm PACKET-ID`. This is attribution, not authentication.
- **No matching evidence.** Check latest revision, permissions and the wording. Lexical retrieval can miss synonyms. Try a source heading or report the evidence gap; never invent an answer.
- **Workspace busy.** Another command holds the OS lock. Retry after it finishes. The lock file remains on disk, but the OS releases ownership when the process exits. Do not delete the persistent lock file to bypass an active writer.
- **Legacy .lock found.** Older releases used a PID sentinel. Stop older brain commands, check the saved PID against your process list and verify no old writer remains. Only then remove that legacy `.lock` file manually. The new `.brain/workspace.lock` must stay in place. Different lock schemes must not write the same workspace concurrently.
- **Interrupted transaction.** Run recover using the workspace's permitted processor. It resumes the import/apply journal. Other knowledge reads/writes refuse until recovery finishes. Preserve journals and receipts. If a manual edit conflicts, restore it from a trusted backup with owner review; do not delete the journal to force progress.
- **Source integrity or target conflict.** Restore an unchanged original from backup, or import a corrected snapshot. Prepare a fresh proposal when evidence/targets change. Do not reuse approval for different wording.
- **Older workspace.** Workspace version 1 remains supported. Select its processor explicitly through settings. Existing topic summaries fall back to the first body line until reviewed updates add full metadata. Old imports remain in their registry; import logging starts with this release. Keep original decisions/journals for reconstruction. Re-propose old pending packets if you want the complete metadata preview and current summary/cadence.
- **Rebuild refused.** Retain the original workspace and backup. Rebuild needs completed matching decisions/journals/receipts and an empty separate destination. Manual edits or missing history require reviewed repair, not fabricated receipts. Daily working notes and credentials are outside reconstruction scope.
- **Credential committed.** Revoke it, restrict access where possible, then follow [GitHub's sensitive-data removal procedure](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository). A deleted current file can remain in history.
- **API permissions or partial export.** Verify account, region, resource, scopes, date window, filters and pagination locally. Mark coverage unavailable or partial until fixed; never print tokens to chat.
